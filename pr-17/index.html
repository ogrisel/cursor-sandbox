Lloyd k-means in the Python array API

What this PR explores

This experiment studies nearest-centroid assignment, Lloyd updates, empty clusters, and centroid initialization through the Python array API. The eager implementation runs with PyTorch on CPU and CUDA and with CuPy on CUDA. Comparisons cover stock scikit-learn, scikit-learn with k-means++ performance patches, Cython, and cuML.

The journal progresses from kernel-fusion probes to bounded-memory tiled assignment, full fits, repeated-seed and shared-start comparisons, empty-center relocation, and greedy versus scalable initialization. The current five-task mix spans 3 to 3000 clusters, 2 to 1000 features, and 135000 to 2100000 samples. Runs use float32, eager execution, TF32 disabled, three seeds, and a 60-second worker limit.

Latest results

017 evaluates catastrophic cancellation in GEMM distances and the selective direct-distance safeguard used by cakedev0's Cython implementation.

Main conclusions:

  • Translation by 1e3 makes plain float32 GEMM choose the wrong center for about 97% of a 100,000-row assignment benchmark and raises inertia 1.63–1.64x.
  • The 1e-2 relative-threshold fallback fixes every tested float32 assignment and recovers all 10 unique k-means++ centers on CPU and CUDA.
  • Sparse fallback keeps most of GEMM's advantage over broadcast, but the Python gather/scatter prototype is 1.7–2.9x slower than bounded broadcast when all pairs trigger.
  • A production path should use selective repair for sparse triggers, switch dense-trigger tiles to bounded broadcast, or fuse the repair into a backend-specific kernel.
