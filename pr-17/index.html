Lloyd k-means in the Python array API

What this PR explores

This experiment studies nearest-centroid assignment, Lloyd updates, empty clusters, and centroid initialization through the Python array API. The eager implementation runs with PyTorch on CPU and CUDA and with CuPy on CUDA. Comparisons cover stock scikit-learn, scikit-learn with k-means++ performance patches, Cython, and cuML.

The journal progresses from kernel-fusion probes to bounded-memory tiled assignment, full fits, repeated-seed and shared-start comparisons, empty-center relocation, and greedy versus scalable initialization. The current six-task mix spans 3 to 3000 clusters, 2 to 1000 features, and 135000 to 2100000 samples, including a balanced 256-cluster, 128-feature case. Runs use float32, eager execution, TF32 disabled, three seeds, and a 60-second worker limit.

Latest results

020 adds k256-d128 and times cuML only after the training data is resident on the GPU. Stock scikit-learn finishes the new full fit in 6.60 s, below the worker deadline.

Main conclusions:

  • Native updates improve k256-d128 shared-start Lloyd by 1.37x on Torch CPU, 1.07x on Torch CUDA, and 1.12x on CuPy.
  • The portable array-API CPU full fit (5.81 s) is 1.14x faster than stock scikit-learn (6.61 s), but 3.50x slower than cakedev0 (1.66 s).
  • With device-resident data for all GPU methods, native CuPy narrowly beats cuML greedy for the full fit (0.478 s versus 0.510 s); cuML scalable is fastest (0.242 s) but ends 0.66% higher inertia.
